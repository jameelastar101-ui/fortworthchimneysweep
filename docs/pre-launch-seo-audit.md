## Fixed since this audit was written

### 1. ~~`/contact-us/` was a 404~~ — fixed
Built at `src/pages/contact-us.astro`: Hero with click-to-call CTA, NAP as text, the shared `ServiceAreas` block, closing CTA band, no form. All 86 header/footer links across the site now resolve.

### 2. ~~Dead internal link `/chimney-cap-spark-arrestor-mesh/`~~ — fixed
Removed from all four blog posts (`chimney-cap-needs-replacing.md`, `chimney-cap-sizes.md`, `chimney-without-a-cap.md`, `top-sealing-damper-vs-chimney-cap.md`) by rephrasing the sentences to state the sphere-test fact directly instead of linking to a guide that was never built.

### 3. ~~`netlify.toml` build command skipped the site's own safety checks~~ — fixed
`netlify.toml`'s build command is now `npm run build`, so the real Netlify deploy runs the image-sitemap generation and the placeholder/price safety checks, same as local builds.

### 4-6. ~~Homepage, 6 blog posts, and the blog index/pagination pages had no `og:image`~~ — fixed
Added `site.defaultOgImage` (`src/data/site.ts`) pointing at the existing `chimney-sweep-fort-worth-hero.webp`, and `BaseLayout.astro` now defaults the `ogImage` prop to it instead of rendering nothing. This is the sitewide fallback `content.config.ts`'s blog schema comment already promised but never had code behind it — one change fixed all of these pages plus the new contact page, with zero per-page edits needed. Pages with their own `ogImage` (every service page, most blog posts) are unaffected.

### 8. ~~Service-page hero/content images were large, unoptimized JPGs~~ — fixed
Converted all 48 unique JPG/PNG images referenced from the 9 affected service pages (`bird-in-chimney-removal`, `chimney-animal-removal-fort-worth-tx`, `chimney-cap-installation-fort-worth-tx`, `chimney-inspection-fort-worth-tx`, `chimney-leak-repair-fort-worth-tx`, `chimney-relining-fort-worth-tx`, `chimney-repair-fort-worth-tx`, `chimney-sweep-services`, `squirrel-in-chimney-removal-fort-worth-tx`) to WebP at quality 82 using `sharp`, same pixel dimensions, no visible quality loss. Total: **36.3 MB → 5.8 MB** (84% smaller) across the 48 files. Frontmatter (`src:` and `ogImage:` fields) updated to match; originals deleted. Rebuilt with zero new warnings and zero regressions (alt text, canonicals, titles, H1s all still clean).

### 7. ~~Raccoon removal service page shipped with zero images~~ — interim fix applied, real photos still needed
`public/images/raccoon-removal/` never existed — squirrel and bird removal each got their own dedicated photo set during the build, raccoon removal didn't. I can't fabricate "real photos of the business's work" (that would violate Section 7's own rule and would be dishonest), so rather than leave the page with broken image references or ship it with no visuals at all, I pointed its `heroImage`, `ogImage`, and the four `images.*` fields at the parent hub's (`chimney-animal-removal-fort-worth-tx`) real, already-existing photos — same business, same generic containment/camera-scope/cap-install work, with alt text that accurately describes what's shown (no raccoon-specific claim, since none is visible). A comment at the top of `raccoon-in-chimney-fort-worth-tx.md` names the five raccoon-specific filenames this is standing in for.

This is a stop-gap, not a real fix: every other animal spoke page (squirrel, bird) has its own unique, species-specific photography, and raccoon removal is now the one spoke reusing its hub's images instead. **Supply five real raccoon-job photos** at the filenames listed in that comment (`public/images/raccoon-removal/raccoon-in-chimney-fort-worth-hero.webp` + 4 more) and swap them in — that's a direct frontmatter edit, no component changes needed.

### 9. ~~LocalBusiness schema's `areaServed` didn't match the service area shown on the page~~ — fixed
`LocalBusinessSchema.astro` hardcoded only Fort Worth and Keller while the homepage's visible `ServiceAreas` section listed 11 cities. Pulled the 11-city list out to `site.areaServed` in `src/data/site.ts` (the file's own stated single source of truth for business facts) and pointed both `LocalBusinessSchema.astro` and `home.ts`'s `areas.neighborhoods` at it, so the schema and the visible copy can't drift apart again. Confirmed in the build: the schema now lists all 11 cities on every page, matching the homepage exactly.

## Low / minor

### 13. Homepage `<title>` — not actually an issue (audit measurement error)
My original scan flagged this as 64 characters, but that counted the raw HTML entity `&amp;` (5 chars) instead of the `&` (1 char) a browser or search result actually displays. The real, rendered title — `Chimney Sweep & Repair in Fort Worth, TX | Chimney Sweep Pro` — is **60 characters**, right at the edge of the ~50–60 char guidance but not over it. No change made; the original flag was a false positive in my own tooling.

### 14. ~~No `favicon.ico`~~ — fixed
Generated `public/favicon.ico` from the existing `favicon.webp` (16/32/48px PNG-in-ICO, the standard modern format) using `sharp` — no new artwork, just a derived format for the crawlers/old clients that still request `/favicon.ico` by default at the site root. No HTML change needed; browsers that honor `BaseLayout.astro`'s explicit `<link rel="icon" type="image/webp">` still use that, this is purely the fallback.
